Mr. Usage › Firecrawl

Check your Firecrawl credits on the desktop

Mr. Usage reads Firecrawl's credit-usage endpoint with your own API key and keeps a card with the credits left, the plan size and the end of the billing period, refreshed on its own.

Install Mr. Usage GitHub repository

What the Firecrawl card shows

Credits left out of the plan, and the end of the billing period. A yellow "Low" badge appears under 20% left and a red "Nearly out" badge under 5%, with a line of today's readings underneath.

Pay-as-you-go accounts can run past zero into an overage allowance. The card clamps the figure at zero and lists the overage separately.

What Mr. Usage reads

AuthenticationAuthorization: Bearer <key>
Verified againsthttps://docs.firecrawl.dev/api-reference/endpoint/credit-usage
Anything else contactedNothing. The host is on a per-provider allowlist checked before every request, redirects are off, and the connection is TLS 1.2 or newer.

The app shows you this exact address before you save a key, and docs/SOURCES.md records where each fact came from and when it was read.

Questions

Does checking my Firecrawl usage cost credits?

Firecrawl's open-source API server bills nothing for this call: its credit-usage controller only reads the balance, and the billing function is never called from it. A live account confirmed it: the credit count did not move across polls.

Where does my Firecrawl API key go?

Into your operating system's credential store, under the service name mr-usage: Keychain on macOS, Credential Manager on Windows, the Secret Service on Linux. The app reads it at the moment it calls the vendor, wraps it in a zeroizing type, and drops it. It is never written to a file of the app's own and never sent back to the window.

How often is the card refreshed?

Every 5 minutes by default. Settings lets you pick anything from 1 minute to 24 hours, and changing the interval takes effect from the last poll. There is also a Refresh button on each card, limited to once a minute.
